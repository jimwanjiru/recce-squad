# Validation evidence

Validated in the published environment's subsequent development instance on 29 October 2026. This is current-instance evidence; no new environment publication or production deployment was performed.

- Prisma 6.19.3 offline WASM/DMMF schema validation passes for all **36 models** and their relationships.
- JavaScript-engine Prisma client generation succeeds without native engine downloads.
- All six committed MySQL migrations apply successfully against isolated MySQL 8.4 databases. Re-running migrations reports them current and preserves checksums.
- Fictional development seeding is repeatable, preserves existing credentials and does not activate personnel policies.
- **46 automated tests pass:** 4 workbook/schema/migration-parser/local-credential checks, 6 policy/date/field-permission unit checks, 17 foundation MySQL/HTTP checks, 8 officer-workflow integration checks, 9 organization integration checks, and 2 Chromium end-to-end tests. No tests are skipped or disabled.
- Integration checks cover authentication, origin/CSRF rejection, Secure/HTTP-only cookie flags, session hashing/expiry/revocation, password changes, RBAC, field restrictions, redacted audit events, duplicate force numbers, foreign keys, temporal constraints, concurrent overlapping primary assignments, unsafe isolation rejection, import staging, nullable movement references and inactive policies.
- Organization checks cover canonical/alias collisions, stale reference updates, hierarchy cycles/concurrency, inactive references, verified baselines, deployment containment, overlapping/concurrent establishments, direct-SQL history protections and redacted audits. Retirement and strength policies remain inactive.
- Metadata verification compares every model scalar column/nullability and foreign key with the migrated MySQL schema.
- Backend and frontend TypeScript checks pass. The production build includes separately loaded React page bundles.
- Officer checks cover registration, exact string identifiers, verified initial history, duplicate prevention, forbidden fields, sensitive writes, stale edits, profile permissions, archive/restore history preservation and bulk-action rollback/success.
- Chromium verifies fictional registration, editing (including rejection of an intervening edit), search, archive/restore, responsive navigation, mobile page-width containment and sign-out/reload, plus changing an account password and signing in with the new password. A second browser workflow exercises ranks, units, sub-units, assignment baselines, deployments and dated approved establishments. Browser testing found and resolved initial session loading and form initialization races; all final checks pass.
- Built-server HTTP smoke passes: live database health, fictional login, authorized listing and logout.
- The Docker package builds from a sanitized context with lockfile installation and successful Prisma/client/frontend generation. A fresh, isolated Compose project becomes healthy and starts with one administrator, zero officers and no retirement/strength rules.
- Docker functional checks verify initial credential retrieval without exposing values, password changes/session revocation, stop/start record persistence, preservation of a removed permission, an unprivileged application user, absence of private files/root database secrets in the app container, and no passwords in startup logs.
- `npm audit --audit-level=moderate` reports zero known vulnerabilities at validation time. Prisma packages are aligned on 6.19.3; narrowly scoped overrides use the patched MariaDB connector, UUID and configuration merge library. The regenerated client, database suite and clean image were revalidated after these changes.
- The source workbook remains ignored and unchanged. No real officers have been imported; test fixtures are fictional.

Native Prisma engine downloads return HTTP 403 for binaries.prisma.sh under the current network policy. Checksum and TLS verification were never disabled. The tested alternative uses Prisma's pinned WASM validator, JavaScript client engine, MySQL driver adapter and a checksum-aware SQL migration runner with the standard Prisma migration ledger. Native CLI migration deployment has not been validated in this environment.

The React officer interface and core officer CRUD/archive/profile APIs are implemented. Organization administration, verified first-assignment baselines, deployment intervals and dated approved establishment records are implemented. The approval-based movement workflow, calculated reports, document uploads and workbook import/export remain subsequent phases. Only explicitly authorized, bounded officer-profile sections expose related records; financial details and raw import-source records remain unavailable through these APIs. Production policy activation, real-data migration, deployment security review and production backup/restore validation remain outstanding.
